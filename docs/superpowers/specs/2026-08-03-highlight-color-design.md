# 笔记正文高亮加颜色（多色高亮）设计

日期：2026-08-03
状态：已批准（用户确认设计各节后转入实施）

## 1. 需求

编辑器内给正文文字加**带背景色的高亮**（类似 Obsidian/Typora 的马克笔效果），支持默认色 + 预设多色。用户通过**选中文字后弹出调色工具条**上色。

核心约束（项目铁律）：**Markdown 源码是唯一事实源**——颜色必须编码进 markdown 语法，装饰器只是只读视觉覆盖层，不存在 AST → markdown 序列化往返。

## 2. 语法规范

```
==默认黄高亮==                  → 默认色（黄色）
=={红}重要内容==  =={蓝}关键结论==  → 7 个命名色：红/橙/绿/青/蓝/紫/粉
```

- 命名色 = `==` + `{色名}` + 内容 + `==`，`{}` 是明确分隔符，无空格规则
- `==文字==`（无 token）为默认色，与 Obsidian/Logseq/markdown-it/Pandoc 生态完全可移植
- **读取别名表**（写入只用中文，读取兼容 Obsidian Hilo / Style Obmd / Better Markdown 插件格式）：

| 中文 | 英文别名 |
|---|---|
| 红 | red, r |
| 橙 | orange, o |
| 绿 | green, g |
| 青 | cyan |
| 蓝 | blue, b |
| 紫 | purple, p |
| 粉 | pink |

- **未知 token**（`=={xyz}内容==`）：按默认黄渲染，`{xyz}` 字面保留在内容中显示——与 Obsidian 原生行为一致，零信息丢失。空括号 `=={}` 同理按字面处理
- 转义：`\==` 输出字面 `==`，不高亮（现有 `Escape` 节点处理自动隐藏反斜杠）
- 嵌套：非贪婪闭合（`==a ==b== c==` 内层先闭合），其余按字面显示
- 高亮内 markdown（加粗/链接等）仍然可用（token 不参与内容）

## 3. 解析机制（livePreview）

在 `src/lib/livePreview.ts` 现有 `buildRanges` 树遍历中新增 `==` 扫描：

1. **只处理 `Paragraph` 和 `Heading` 节点**——`InlineCode`、代码块、HTML 块天然被排除
2. 对节点文本跑正则（含别名表），匹配时沿用现有模式：
   - `Decoration.replace`（或 `hideInline` + `lp-inline-hidden`）隐藏 `==` 与 `{色名}` 标记
   - `Decoration.mark({ class })` 上色：`.lp-hl`（默认色）+ `.lp-hl-red` 等修饰类（类名统一用**英文**色名，与别名表同表映射）
3. 跳过已被 `InlineCode`/`Escape` 覆盖的偏移范围

正则骨架（实现细节可调）：

```
/==(\{([^}=]*)\})?([^=]*?)==/g
```

- `{色名}` 命中别名表 → 命名色；未命中 → 默认色且 token 字面保留
- 无 `{…}` → 默认色

## 4. 渲染与主题

`src/index.css` 新增 8 组设计 token（亮/暗双版）：

- `--hl-yellow`（默认）、`--hl-red`、`--hl-orange`、`--hl-green`、`--hl-cyan`、`--hl-blue`、`--hl-purple`、`--hl-pink`
- 每组含 `bg`（浅底）+ `fg`（深字）；`.dark` 下背景加深、文字变浅，保证两主题可读性
- `.lp-hl`（默认色）+ `.lp-hl-red` 等修饰类（英文色名，与别名表同表映射），`border-radius: 2px; padding: 0 2px` 呈现马克笔效果
- 亮暗切换自动生效（token 体系，无需额外代码）

## 5. 工具条交互与写回

**触发**：编辑器内产生非空选区（鼠标拖选或 Shift+方向键）时浮出工具条。用 CM6 原生 `tooltip` facet（`showTooltip`）实现——位置自动锚定选区上方，滚动/失焦自动隐藏，不干预编辑器布局。空选区不弹。

**工具条内容**：8 个圆形色块（默认黄 + 7 命名色，与渲染色一致）+「清除」按钮（斜杠圆）。

**写回源码**（点击色块）：

1. 单事务：把每个选区包裹为 `==内容==`（默认色）或 `=={色名}内容==`（命名色）
2. 跨行选区按行拆分逐段包裹（高亮不跨段落）
3. 幂等/清除：选区已在同类高亮内 → 点击同色 = 剥除；点击「清除」→ 剥掉任何 `==` 包裹
4. 全部经 CodeMirror 事务 → 撤销/重做栈原生可用
5. 工具条用 tooltip 的 `pos` + 状态字段记录选区，点击色块失焦后仍能正确写回

**源码模式**：`==` 原样显示为文本（与 `**` 行为一致），可手改。

## 6. 导出兼容

- `src/lib/export.ts`（marked 渲染）：注册 `highlightExtension`——`=={红}文字==` → `<mark class="hl-red">文字</mark>`；`==文字==` → `<mark class="hl-default">`；未知 token 原样保留（与编辑器降级一致）
- `src/lib/exportStyles.ts`（HTML/PNG 导出样式）加 8 组 `.hl-*` 颜色（与编辑器同 token 值，亮暗双版）
- `exportRich.ts` 公式/图表占位符机制不受影响——`==` 扫描在 marked 层做，无冲突

## 7. 边界情况

| 情况 | 行为 |
|---|---|
| 空选区 | 不弹工具条 |
| 选区跨行 | 按行拆段，逐段包裹 |
| `==` 在行首 / 列表内 / 标题内 | 正常高亮（树遍历覆盖 Paragraph/Heading） |
| 代码块 / 行内代码 / HTML 块内 `==` | 不处理（树遍历天然排除） |
| `\==` 转义 | 字面输出，不高亮 |
| 嵌套 `==` | 非贪婪，最近闭合优先，其余字面 |
| 未知 token `=={xyz}==` | 默认黄 + token 字面保留 |
| 点击当前高亮色 / 「清除」 | 剥掉包裹，恢复纯文本 |
| 撤销 | CM6 事务原生支持 |

## 9. 兼容性决策记录

调研结论（2026-08-03，经 web 检索核实）：

- 多色高亮**没有跨应用标准**；唯一普适的是 `==text==` 默认黄
- Highlightr（Obsidian 最流行插件）用 HTML `<mark>`（`<mark class="hltr-pink">` / inline style），高亮内粗体/链接失效——**不用** HTML 方案
- Hilo / Style Obmd / Obsidian Better Markdown 用 `=={token}…==` 结构（英文 token）——选用同结构，中文 token 写入 + 英文别名读取，双向兼容
- jot 写出的笔记在无插件 Obsidian 中显示为黄底含 `{红}` 字面，内容不破坏、颜色降级可接受
- 曾考虑 `==-色名 …==` 前缀语法，已否决（无生态支持、空格规则脆弱）
- 色名用中文（用户决定），别名表弥补英文生态互通

## 10. 范围外（YAGNI）

- 侧边栏文件/文件夹着色（用户明确只要正文高亮）
- 自定义任意颜色（调色板任意色）——暂只支持 8 预设色
- Highlightr HTML `<mark>` 读取
- `==` 语法在源码模式下的语法高亮着色
